# TaxAI.pk: exact Git and Vercel setup

The site now stores waitlist entries in private Neon Postgres storage connected through Vercel. `/admin` uses browser password authentication, exports CSV, supports manual deletion, and removes entries automatically after seven days.

## 1. Files to update in Git

Replace the old website files in your repository with the complete contents of this package. Commit and push these paths:

Do **not** commit `.env`, database URLs, passwords, or secrets.

## 2. Connect private Postgres storage in Vercel

Vercel Postgres itself is no longer offered for new projects. Its current replacement is a Postgres integration from the Vercel Marketplace. Use Neon:

1. Open your Vercel project.
2. Select **Storage**, or open **Marketplace → Neon**.
3. Install **Neon Postgres**, choose **Create New Neon Account**, and connect it to this Vercel project.
4. Choose the free plan if it meets your expected volume and select a region near your Vercel Functions.
5. Confirm that the integration added `DATABASE_URL` under **Project Settings → Environment Variables** for **Production**. Add it to Preview only if you intentionally want preview deployments using a database.

The database table and index are created automatically on the first form submission or admin visit. No SQL needs to be pasted manually.

## 3. Add the three Vercel environment variables

Open **Project Settings → Environment Variables** and add these for **Production**:

| Name | Value |
|---|---|
| `ADMIN_USERNAME` | Your chosen admin username, such as `taxai-admin` |
| `ADMIN_PASSWORD` | A unique password generated by a password manager, preferably 20+ characters |
| `CRON_SECRET` | A separate random value of at least 32 characters, using letters and numbers |

Never reuse the admin password as the cron secret. Do not prefix or suffix the values with quotation marks.

## 4. Deploy

After pushing the Git changes, open Vercel → **Deployments** and confirm the new production deployment succeeds. If Vercel built a deployment before you added the environment variables, redeploy it after all variables are present.

The daily retention job is registered from `vercel.json` and runs at 02:15 UTC on production. It permanently deletes entries whose seven-day expiry has passed. Expired entries are also purged when the admin page is loaded or a new submission arrives.

## 5. Test safely

1. Submit one test entry on `/`.
2. Open `/admin`. Your browser should request the configured username and password.
3. Confirm the test row appears.
4. Select **Download CSV** and open the downloaded file.
5. Select the test row, choose **Delete selected**, and approve the confirmation.
6. Reload `/admin` and confirm the row is gone.

CSV export does not delete entries. Deletion happens only through **Delete selected** or automatic seven-day expiry.
